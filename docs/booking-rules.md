# Правила бронирования

Единый свод бизнес-правил системы. Все суммы — виртуальные начисления,
онлайн-оплата в MVP не проводится.

## 1. Роли

| Роль | Права |
|---|---|
| `user` (клиент) | каталог, брони, отмены, споры |
| `owner` (арендодатель) | свои позиции, часы работы, тарифы, свои брони, выдача и возврат |
| `admin` | всё + арбитраж споров, роли, модерация |

Роль выбирается при регистрации (`user` или `owner`), `admin` только назначается.

## 2. Время

- Хранение — UTC (`timestamptz`). API принимает и отдаёт ISO 8601 **со смещением**;
  запрос с «наивным» временем отклоняется (422).
- Интервал брони — полуоткрытый `[start_at, end_at)`: стыковка без конфликта.
- Сетка — 30 минут.
- Часовой пояс:
  - правила (рабочие часы) считаются в поясе **позиции** (`equipment.timezone`);
  - отображение — в поясе **пользователя** (`users.timezone`);
  - источник пояса: браузер → профиль → пояс позиции → `Europe/Moscow`;
  - IP-геолокация не используется (VPN не влияет на правила).

## 3. Тарифы и цена

- У позиции может быть один или два тарифа: `price_per_hour` и/или `price_per_day`.
- Минимумы: `min_hours`, `min_days` (по умолчанию 1).
- Максимумы: `max_hours` (по умолчанию 24), `max_days` (по умолчанию 30),
  платформенный потолок `MAX_RENTAL_DAYS=90`.
- Клиент выбирает `billing_unit` при бронировании; сервер считает оба варианта
  и подсказывает более выгодный.

```
часы = max(1, ceil(минуты / 60))
сутки = max(1, ceil(минуты / 1440))
total = единицы × unit_price × quantity
```

Сутки — 24-часовые блоки. Для короткой аренды «на день» арендодатель задаёт
часовой тариф, и клиент увидит более дешёвый вариант.

## 4. Ограничения брони

| Правило | Значение |
|---|---|
| Запас до начала | `equipment.lead_time_minutes` (по умолчанию 30) |
| Горизонт | 90 суток вперёд |
| Максимум активных броней у клиента | 10 |
| Дубли | запрет пересечения своих броней на одну позицию |
| Рабочие часы | начало, конец и выдача внутри интервалов пояса позиции |

Конфликт: сумма `quantity` пересекающихся подтверждённых броней плюс запрошенное
превышает `equipment.quantity`. Проверка расширяется на
`equipment.buffer_minutes` (по умолчанию 30).

## 5. Статусы

```
confirmed ─► completed
    ├─► cancelled
    ├─► terminated  (досрочный возврат)
    └─► no_show
```

`confirmed` создаётся сразу при бронировании. Все действия пишутся в `booking_events`.

## 6. Выдача и возврат

- Арендодатель отмечает выдачу; возможна раньше `start_at` — **бесплатно**,
  конец аренды не меняется (`returned_at`/`end_at`).
- Запросить раннюю выдачу может и клиент, подтверждает арендодатель.
- Проверка доступности: `[picked_up_at, end_at + buffer)`.
- Добровольный досрочный возврат: возврат за неиспользованные полные единицы.
- Неявка: окно `clamp(25% длительности, 15 мин, 2 ч)`, дедлайн —
  `min(start + окно, end − 5 мин)`. Фиксируется автоматически планировщиком
  (фоновый воркер раз в 5 минут), арендодатель может снять в течение часа.

## 7. Отмена

### Автоматически

| Случай | Возврат | Штраф / компенсация |
|---|---|---|
| Клиент > 2 ч до начала | 100% | — |
| Клиент ≤ 2 ч до начала | 95% | 5% (`CLIENT_LATE_CANCEL_PERCENT`) |
| Техническая отмена (20 мин после создания и > 24 ч до начала) | 100% | — |
| Арендодатель > 24 ч до начала | 100% | счётчик отмен +1 |
| Арендодатель ≤ 24 ч до начала | 100% | +10% компенсации, счётчик +1 |
| Досрочный возврат | за неиспользованные единицы | — |
| Неявка | 95% | 5% |
| Отмена админом | 100% | — |

### Через админа

| Случай | Решение |
|---|---|
| Оборудование не работает | возврат неиспользованного + 10%, инцидент арендодателю |
| Повреждение клиентом | возврат не начисляется, сумму ущерба вводит админ |
| ЧП клиента до начала | штраф снимается |
| ЧП клиента после начала | возврат 0–100% на усмотрение админа |
| Форс-мажор арендодателя | без счётчика и компенсации |
| Частичное решение | любые суммы вручную |

Маршрут определяется **причиной из формы**, а не стороной. Слот освобождается
сразу, деньги замораживаются до решения.

## 8. Споры

- Один спор на бронь; создаётся только при наличии сумм (> 0).
- Обязательное описание ≥ 50 символов.
- Квоты: 3 активных спора, 10 за 30 дней, rate limit 5/час.
- Репутация: > 50% отклонённых из последних 10 при ≥ 5 спорах →
  30 дней предмодерации без автоснятия штрафа.
- 48 часов без решения → штраф 5% снимается автоматически;
  требования по ущербу остаются открытыми.
- Оспаривание авторешений: 24 часа, один раз на бронь.

## 9. «Интеллект»

1. Проверка пересечений: интервалы, вместимость, буфер, рабочие часы,
   блокировка строки оборудования (`SELECT ... FOR UPDATE`).
2. Content-based рекомендации: косинусное сходство по `specs`, категории,
   бренду и цене + блок «популярное» по броням и просмотрам за 30 дней.
3. Прогноз загрузки: SQL-агрегация по дням недели и часам на основе
   фактических выдач.

## 10. Ограничения MVP

Онлайн-оплата и залоги, уведомления, загрузка фото, оценка ущерба,
лист ожидания, рейтинги и отзывы, повторные апелляции, деплой в интернет.
